# Benchmark 质量与验收边界

本版依据需求中的用户可观察行为建立断言。精确角色、名称、身份、权限和结果保留；普通可见文本不被额外限定为链接，原生和 ARIA 下拉通过各自公开交互选择相同标签。

## 输入完整性

`npm run test:collect` 解析全部需求，检查重复 YAML key、全局身份、Given/When/Then、叶节点场景、引用、图片边界和文件摘要。正式测试的逐需求用例数量须与场景数量一致；新增或遗漏的用例都会失败。该检查证明身份和数量完整，不单独证明每个复合结果子句的语义都已充分覆盖。

`revision.json` 冻结单题需求、参考图片、正式测试、独立控件副本和 setup 生成器。公共控件副本须与已验证模板逐字一致。父版本清单和旧验证记录保留在 validation 下，原实验输出不参与修订。

## 有效实现与失败边界

控件回归同时验证原生/弹出选择、公开标签与私有 value 区别、无隐式 textbox 角色的密码、密码初始遮蔽、装饰标记、重复文本、嵌套/平级 Answers、分页和固定业务时钟。负例覆盖错误角色、错误名称、重复身份、错误顺序、隐藏/禁用选项和明文登录密码。

浏览器求值只读取公开 DOM 的原生属性或区域包含关系，未读写应用存储、私有 API 或内部变量。创建业务对象仍走各题的原有 UI 流程。动作定位保持唯一，存在性检查允许多份可见的相同文本。

## 初态、共享数据与预算

每次正式评测从隔离应用副本和全新数据目录开始。逐场景的服务端初态恢复仍未由现有脚本实现：测试集内 UI 数据会保留，可能污染复用账户的后续场景。当前不得把新 BrowserContext 等同于服务端数据隔离，详见 CONSISTENCY.md。排序测试遍历公开分页来比较指定历史身份，其他 case 创建的对象不应被视作不存在。角色账户、父对象和业务名称用于区分记录。

StackOverflow 评论入口以认证用户为初态；徽章目录从公开 Users 中的 Helpful User 资料进入。上述初态与路径已经写回源需求，不由测试单独隐含约定。

单场景 60 秒、断言 10 秒、动作 15 秒、导航 30 秒、1 worker、0 retry。测试预算属于评测协议，不代表产品必须达到同样的性能指标。两种方法使用同一个冻结协议。

## 证据与适用范围

场景收集、类型检查和控件回归是跨题合同验证；完整应用的端到端结果按题目、产物、需求摘要与报告分别登记。当前存在的 BookStack 应用可用于端到端回归，其他题目仍需相应应用验证业务流程、持久化、跨账户权限和数据计算。

本版利用已观察的 StackOverflow 错误修订公共合同，属于开发阶段。正式报告应冻结本版后统一评测各方法，保留历史分数，并用未参与此次修订的任务检验泛化。
