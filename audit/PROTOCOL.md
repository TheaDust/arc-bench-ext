# Independent task review protocol

Review all requirement leaves and all scenarios in your assigned task, including inherited parent/root descriptions, helper code, and reference evidence when relevant. Never inspect generated agent applications or their scores to choose expected behavior. Source of truth is the stated user behavior; distinguish original semantics from newly introduced public benchmark conventions.

For every scenario record requirement ID, scenario ID/name, test file, Given/When/Then coverage, risks and disposition in a task-specific JSON matrix. A clean row requires an actual review, not only a filename or count check. Map every explicit result clause; flag missing assertions as false-positive risks as well as unnecessary structure/text/role constraints as false-negative risks. Also review setup, identity, state transitions, persistence and permissions.

Fix only demonstrable mismatches within your task directory. Preserve explicit roles, labels, object/owner identity, values, ordering, and outcomes. Do not use arbitrary first matches, implementation CSS, test IDs not specified publicly, app internals/private APIs, global unrelated text, permissive catches or removed business assertions. Multiple equivalent public presentations may be accepted only if they establish the same obligation. Clarify requirements only for a real ambiguity, disclose changed interpretation, and mark affected historical apps/results as non-comparable. Do not invent unseen business policies. Defer unresolved source ambiguities explicitly.

Write audit/<task>.md and audit/<task>.json. JSON must contain task, reviewedRequirements, reviewedScenarios, scenarios (one row for EVERY scenario, with requirementId, scenarioId, testFile, coverage, findings, disposition), findings (id, severity, category, source, test, explanation, resolution, validation), changedFiles, limitations. Use relative paths and source line references. Include a concise source-to-assertion account in coverage (object preferred). Add task-specific positive and negative contract tests in audit/validation/<task>.spec.ts for substantive oracle changes. Tests must distinguish legitimate presentation variants from wrong value/identity/state/permission. Do not change shared validation files, revision.json, root docs or other tasks. Parent agent integrates and freezes.

You may run read-only analysis and small local tests; no model calls, generated-app edits, external benchmark edits, full controller tests, or mass application evaluation. Parent will execute collected browser checks. The source is a derivative benchmark; never claim these edits change untouched upstream official tests.
