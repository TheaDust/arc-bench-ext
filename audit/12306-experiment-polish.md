# 12306 正式实验题面打磨

沿用 93 条原子需求、142 个场景，以及原有场景、步骤 ID 和测试标题。没有新增功能、账户、车次或状态。

| 范围 | 统一的口径和验收 |
| --- | --- |
| ROOT、REQ-5、REQ-8 | 区分种子、UI 准备和正式操作；按场景所给日期和车次建立行程，乘客归属当前账户，订单归属确认该订单的账户。 |
| REQ-8.3、REQ-8.4 | Place order 只打开确认，Confirm 才生成未支付订单并锁座；说明已有倒计时首次读数容差，重载不重置。 |
| REQ-5.3.3 | 续付同一笔未支付订单，不只识别同一车次。校验 Order details 内同一车次、乘客、证件号和席别，并保留 Payment information 可见断言。 |
| REQ-8.5、REQ-8.6、REQ-8.7 | 分开已支付、未支付和已取消。重载后按同一分类核对状态；需要时重开分类，不要求 UI 记住当前标签。 |
| REQ-8.8、REQ-5.5 | 两个取消场景的未支付订单都走 UI 创建；退款的准备明确包含 Pay，完成后按原路径进入历史订单。 |

本轮不新增跨账户争抢、支付超时、并发或退款边界场景。重订可进入确认是现有释放座位的公开证据，不能证明并发库存正确。没有对候选应用执行 142 个业务场景。正式比较应冻结同版输入后再运行，旧分数不直接迁移。
