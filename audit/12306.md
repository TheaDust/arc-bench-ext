# 12306 逐题审查

已完整核对 93 条原子需求、142 个场景、全部测试/公共 helper、父级合同及种子说明；未读取任何生成应用或成绩。需求、场景 ID、数量、种子均未更改。逐场景 GWT、断言与语义审查见 [12306.json](12306.json)。

- **12306-F01 (medium, false-negative, fixed)** Repeated visible feedback, route or mailbox text need not be globally unique. Shared text() formerly used strict toBeVisible on all exact matches. text() now checks at least one visible match; action locators stay strict.
- **12306-F02 (medium, false-negative, fixed)** Login/refund feedback prose did not explicitly require an ARIA status role; status-only lookup rejects plain visible feedback. Use visible feedback containing required success wording and retain real downstream identity/state assertions.
- **12306-F03 (medium, false-positive, fixed)** Result membership was read only from rows having Book; an extra displayed train lacking that action disappeared from the oracle. Enumerate displayed rows by the independently identifiable train number, including rows lacking Book.
- **12306-F04 (medium, false-positive, fixed)** Homepage presence/count did not prove visible search fields, and carousel could accumulate all banners. Require field visibility and previous banner hidden after each change.
- **12306-F05 (high, false-positive, fixed)** Opening Login could authenticate by navigation; anonymous personal center and quick booking entry omitted explicit negative content checks. Assert missing Sign Out after Login navigation and missing protected center/booking content on intercepted entry.
- **12306-F06 (high, false-positive, fixed)** Zero holder Delete controls also passed when the account-holder passenger row was absent. Require visible holder row before verifying its Delete action is absent.
- **12306-F07 (medium, false-positive, fixed)** Question heading in any panel or global page could satisfy destination even when selected category did not contain it. Bind unique selected known category to its exact named panel and scoped target heading; preserve implementation-defined category mapping for three quick questions.
- **12306-F08 (medium, false-positive, fixed)** Mailbox outcome used global email presence, allowing unrelated profile/header text to satisfy security-mailbox result. Scope expected saved/original address to Security mailbox region before/after reload.
- **12306-F09 (medium, coverage-gap, fixed)** Reload did not recheck restored Edit, and batch deletion never checked persisted result. Add named Edit after reload for contact/passenger-type updates; add persisted batch absence and retained holder.
- **12306-F10 (high, coverage-gap, deferred)** Described branches have no scenarios: successful password recovery, essential-profile update, mobile update/cancel, booking-date mode, passenger invalid mobile/cancel, selected-subset/cancel batch deletion, Child and standing-ticket choices. Disclosed; adding scenario IDs and branch specifications changes benchmark denominator and needs a new explicit expansion rather than pretending 142 scenarios cover all prose.
- **12306-F11 (medium, ambiguity, deferred)** Selected-train fare examples are asserted as whole concatenated text; equivalent table/line presentation can fail despite correct values/associations. No arbitrary CSS/ancestor or unassociated global-number fallback added. Needs an association-preserving public-DOM oracle or source-reviewed fare presentation clarification.
- **12306-F12 (medium, false-positive, fixed)** openAgreement selected the first visible link although its source explicitly requires exactly one link of each name. Restore strict unique named link click; duplicates are rejected, without changing other presence checks.
- **12306-F13 (medium, coverage-gap, deferred)** Some description-level identity, no-mutation, details and permissions obligations are weaker than existing scenario assertions. Keep narrower scenario coverage explicit; do not infer correct account storage, full profile values, unrelated-record preservation or account isolation merely from labels/feedback.
- **12306-F14 (medium, coverage-gap, fixed)** 父代理复核发现原场景已明确 Total 位于 Order details，因而可以直接绑定该已有区域，并检查已有 Payment information 区域可见。新增正确支付详情、错误本单金额被旁处正确金额掩盖、缺失支付信息三个正反例；没有新增 UI 合同。
- **12306-F15 (medium, false-positive, fixed)** Login entry accepted an unmasked text input despite shared source requiring a password input. Assert type=password in the dedicated public login entry scenario.
