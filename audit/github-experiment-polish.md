# GitHub 正式实验题面打磨

沿用上一版 49 条原子需求和 104 个场景。未新增账户、功能、场景、权限组合或合并条件；需求、场景、步骤 ID 和测试标题保持原样。

| 范围 | 统一的口径 | 对应验收 |
| --- | --- | --- |
| REQ-2.3 | 分开组织成员、团队成员与仓库授权。 | 授权和降级观察同一行的当前 Role；重载验证持久化与去重。 |
| REQ-6、REQ-6.1、REQ-6.3 | 区分当前 compare 提交、创建时的提交、旧审批和历史评论；旧检查成功不适用于新提交。 | 保护设置使用原题面控件名；在 Checks 页面更新状态。旧审批与评论仍由 REQ-7 的既有场景观察。 |
| REQ-6.5 | 分开合并资格、确认时复核和成功写入；成功场景只验成功路径，缺审批单独验。 | 保留双亲、文件树、历史、PR 状态和重载检查。草稿、冲突、失败检查等仍是业务规则，不计作这个成功场景已覆盖。 |
| REQ-7.1、REQ-7.2 | 共用种子由父需求声明；旧窗口的操作仍按原规则拒绝。 | 保留四个交互场景的原有断言，包括审批和检查独立生效、权限降级和只写一次合并提交。 |

输入审计逐条匹配 GitHub 的 104 个场景与 Playwright 标题，并校验冻结摘要。原有检查场景仍未独立排除检查设置人被导航中同名用户误匹配，也未覆盖全部权限组合。尚未在候选应用上执行本版业务场景。正式实验请让各方法使用同一修订和固定种子，重新准备并执行；旧分数不直接迁移。
