# Keep 逐需求与场景审查

完整阅读 **16 条原子需求、33 个场景**、全部父级合同、16 份 spec、helpers、visual oracle 和隔离身份 fixture。逐场景原文 Given/When/Then、结果义务映射、当前测试行号及审查结论见 [keep.json](keep.json)。没有读取生成应用或得分；需求、场景 ID、标题和分母没有变化。

## 已修复

- **KEEP-01**：同一唯一笔记内可以重复展示相同标题、内容或标签；普通文本改为作用域内可见存在性检查。笔记对象和动作仍严格唯一。
- **KEEP-02**：多个删除/归档操作可以产生多个同名状态通知；反馈存在性不再要求唯一。实际 Undo/Dismiss 动作仍保留明确定位。
- **KEEP-03**：空子集合曾在父级 Deleted notes 完全缺失时通过。现在要求唯一、未隐藏的公开集合存在。父代理正例发现空集合可以是零面积，已改用角色计数而非面积可见性，并保留零面积正例。
- **KEEP-04**：可选确认框和已空列表同时出现会触发严格 OR 歧义。现在分别观察两个公开状态，有确认则点击，并统一验空。
- **KEEP-05**：颜色场景只验证按钮改名，违反原 Then 的“仅动作名变化不足”。两个正式场景现在调用已有的截图像素背景检查；绿色徽标不能代替笔记背景。
- **KEEP-06**：单列列表原来强制左边缘差小于 3px。现在检查所有卡片存在共有垂线、纵向不重叠，容许同列居中和不同宽度；Grid 的多列、状态与内容检查保留。
- **KEEP-07**：允许一个笔记有多个匹配片段，并逐个检查可见的 Highlight st 内容准确，不再要求只出现一次。
- **KEEP-08**：创建标签后的最后 Done 补上管理对话框关闭断言。
- **KEEP-09**：移除的普通内容/标签只要求旧文字不再可见，不会因保留隐藏 DOM 而误判；持久化和过滤结果继续检查。
- **KEEP-13**：Trash/Archived 正面结果现在绑定原文声明的具体集合及笔记身份；页面其他位置的同名预览不能代替列表成员。

## 保留的边界

- **KEEP-10**：描述级键盘可达性、独立图标、搜索高亮视觉区别、Undo 后重载、第二个设置项的保存/取消行为没有被所有现有场景完整验证。当前矩阵不把角色存在等同于这些行为正确。
- **KEEP-11**：相邻块级节点的多行内容文本、裁剪的屏幕阅读器专用文字，仍可能与 Playwright 的文本/可见性解释不同；没有引入应用 CSS 或内部状态兜底。
- **KEEP-12**：Empty Trash 以集合内 region 作为笔记计数；若实现额外放入非笔记的辅助命名区域，现有公开身份不足以消除该潜在歧义。没有为此强加新包装结构。

已有浅绿色像素阈值属于有限的视觉观察，不是截图相似度，也不足以保证接受所有人类会称为浅绿色的色值。本轮没有量化真实应用假阴性率。

## 验证

修改限于本题测试与 helper，没有修改控制器。相关全部 Keep TypeScript 文件及新增合同已通过定向类型检查，因此不需要控制器全量测试。`audit/validation/keep.spec.ts` 当前 **21 条**正反例覆盖重复文本/通知、对象及集合归属、可选确认、空集合缺失/隐藏/重复、合法单列与错误布局、多高亮和真实背景。父代理统一执行，最终结果以 `audit/contract-results.json` 与根 `validation.json` 为准。

这份记录证明逐场景审查完成和定向修订范围，不代表运行过 33 个真实 Keep 应用场景，不声称零假阴性。后续各方法应使用相同冻结版本。
